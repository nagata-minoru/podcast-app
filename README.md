ポッドキャストアプリの本体です。React Native + Expo（TypeScript）で作っています。
画面設計と決定事項は、親フォルダの資料にまとめています。

- `../README.md`：画面構成と画面遷移図
- `../docs/podcast-app-wireframes-revised-v4.pptx`：画面設計・ワイヤーフレーム
- `../docs/implementation-plan.md`：実装方針と決定事項
- `../docs/show-detail.md`：番組詳細画面の仕様
- `../docs/podcast-source.md`：既存のポッドキャストを聴くための設計（RSS の URL で追加）

## 必要な環境

- Node.js
- Yarn 4（`package.json` の `packageManager` で 4.18.1 を指定）
  - Yarn 1 系が入っていれば、`mobile/` の中では自動で 4.18.1 が使われます。
  - React Native は Yarn の PnP 方式に対応していないため、`.yarnrc.yml` で `nodeLinker: node-modules` を指定しています。
- iOS で確認する場合は Xcode のシミュレータ、Android で確認する場合は Android エミュレータ、または実機の Expo Go

## セットアップと起動

```sh
cd mobile
yarn install
yarn expo start
```

起動後、表示される案内に従って `i`（iOS シミュレータ）、`a`（Android エミュレータ）を押すか、
Expo Go で QR コードを読み取ります。

Web では起動できません。`react-native-web` と `react-dom` が入っていないためです。

## よく使うコマンド

| コマンド | 内容 |
| --- | --- |
| `yarn expo start` | 開発サーバーを起動する |
| `yarn typecheck` | 型チェック（`tsc --noEmit`）を行う |
| `yarn lint` | ESLint（`eslint-config-expo`）で検査する（`expo lint` を実行） |
| `yarn test` | テスト（Jest）を実行する。`yarn test --watch` で変更のたびに実行する |
| `yarn e2e` | E2E テスト（Maestro）をシミュレータで実行する。準備は「E2E テスト」を参照 |
| `yarn expo install <パッケージ>` | SDK に合うバージョンでパッケージを追加する。`yarn add <パッケージ>` は使わない |
| `npx expo-doctor` | 依存関係と設定の問題を調べる（expo-doctor は依存に含めていないため `npx` で実行する） |

npm は使いません。`package-lock.json` を作らないよう、`npm install` は実行しないでください。
バンドラーは Expo 標準の Metro を使います。Expo Router が Metro を前提にしているため、Vite は使いません。

| `storage.test.tsx` | 端末への保存（値、再生位置の差分の書き込み、追加した番組の順、消したときの戻り）と、開き直したときに設定・フォロー・追加した番組・再生位置が残り、再生中の回は残らないこと、開発中の入口（`/dev-reset`）で消えること |
| `addFeed.test.tsx` | RSS の URL で追加する画面（成功、再生で長さが直ること、4種の失敗）、取得の打ち切り、番組の一覧の入れ替え |

| `theme.test.ts` | 両テーマの色のコントラスト比（文字と背景の組が 4.5:1 以上） |
| `showDetail.test.tsx` | 番組詳細の操作（フォローと「元に戻す」、もっと見る、絞り込みと番組内検索、行内の再生、保存、番組だけの再生速度）と、番組の非表示（各画面からの除外、取り消し、保存済みと履歴の削除、検索の完全一致、設定からの再表示） |

画面遷移のテストは `expo-router/testing-library` の `renderRouter` で、シミュレータなしに動かします。
Jest では expo-audio の代わりに `__mocks__/expo-audio.ts` を使います。音は鳴らさず、再生中は 0.5 秒ごとに
位置を速度の分だけ進めるので、`jest.advanceTimersByTime` で再生の進み方を確かめられます。
URL の音声（`{ uri }`）は長さ 600 秒、同梱の音声は長さ 0 として知らせます。
RSS の取得は `globalThis.fetch` を差し替えて確かめ、外へは通信しません。
expo-sqlite の代わりに `__mocks__/expo-sqlite.ts` を使います。Node に入っている `node:sqlite` のメモリ上のデータベースで
同じ SQL を動かします（フラグなしで使える Node 22.13 以上が必要。CI は Node 24）。テストごとに保存を消します（`jest/setup.ts`）。

## E2E テスト

[Maestro](https://maestro.dev/) で、シミュレータの Expo Go を実際にタップして確かめます。
手順は `.maestro/flows/` に、毎回の起動手順は `.maestro/subflows/launch.yaml` に置きます。

| ファイル | 内容 |
| --- | --- |
| `01-home.yaml` | 起動するとホームが開き、続きから再生とトップ番組が見える |
| `02-tabs.yaml` | 下部の4タブを順に切り替える |
| `03-show-detail.yaml` | 新着・おすすめから番組詳細を開き、戻るボタンで戻る |
| `04-settings.yaml` | プロフィールボタンから設定を開き、テーマを切り替え、非表示にした番組へ進む |
| `05-player.yaml` | エピソード行で再生を始め、ミニプレイヤーから再生画面を開いて操作し、番組名から番組詳細へ移る |
| `06-main-screens.yaml` | 注目の特集、検索結果からのフォローとライブラリへの反映、履歴の再生位置 |
| `07-show-detail-actions.yaml` | 番組詳細でのフォロー解除と「元に戻す」、エピソードのメニューからの保存、番組の非表示と設定からの再表示 |
| `08-walkthrough.yaml` | 通しの確認。4タブを巡ってもミニプレイヤーが残る、再生画面を閉じると同じタブに戻る、タブごとの画面履歴が保たれる |
| `09-audio.yaml` | 実際の音声の位置で表示が進む、30秒進むで音声の位置も動く、最後まで鳴るとミニプレイヤーが消える |
| `10-rss-feed.yaml` | RSS の URL で追加する（失敗の表示、成功とフォロー、長さのない回の再生、音声のない回、検索への戻り） |
| `11-persist.yaml` | RSS で追加した番組と検索からのフォローが、Expo Go を止めて開き直しても残る |
| `12-feed-refresh.yaml` | 番組詳細の「⋯」の「フィードを更新」で新しい回が増えて更新の時刻が出て、ライブラリの登録済みにも出る |

毎回同じ状態から始めるため、起動手順（`launch.yaml`）は、Expo Go を開いたあとで開発中だけの入口 `/dev-reset`
（`src/app/dev-reset.tsx`）を開き、「保存を消してホームを開く」を押します。端末に保存したものを消して、ホームを開きます。
開発ビルド以外では、この入口は何も消さずにホームを開きます。

- Expo Go は、止めた状態から開くと URL のパスを使いません。そのため、先に普通に開いてから入口を開きます。
- Expo Go は、開いているときに入口の URL を受けると、アプリを読み込み直します。読み込み直したあとに出るボタンを押すことで、
  読み込み直す前の画面を操作しないようにしています。

準備（初回のみ）:

1. Maestro を入れる（Java も一緒に入る）。
   ```sh
   brew tap mobile-dev-inc/tap
   brew install mobile-dev-inc/tap/maestro
   ```
2. Homebrew の Java はパスが通らないため、`yarn e2e` は `JAVA_HOME` が未設定なら
   `/opt/homebrew/opt/openjdk/libexec/openjdk.jdk/Contents/Home` を使います。`maestro` を直接実行する場合は、
   `~/.zshrc` などで `JAVA_HOME` を設定してください。
3. Expo Go の開発メニューの歯車ボタンは、右上のボタン（プロフィール、番組の「⋯」）に重なってタップを邪魔します。
   起動手順（`launch.yaml`）が URL に `__expo_disable_fab=1` を付けて出さないので、手で切る必要はありません。

実行:

```sh
yarn expo start   # 別のターミナルで開発サーバーを起動しておく（ポート 8081）
yarn e2e
```

`yarn e2e` は、架空の番組「試し聴きラジオ」のフィードと音声を配るテスト用のサーバー（`scripts/test-feed-server.mjs`）を
`127.0.0.1:8090` で起動し、終わると止めます。ポート 8090 を空けておいてください。
取り直しの確かめには、配るたびに3本と4本を交互に返す架空の番組「増えるラジオ」（`/growing.xml`）を使います。
音声は `assets/audio/` の読み上げ音声を使い、外へは通信しません。

起動中のシミュレータが複数あるときは、`maestro --device <UDID> test .maestro/flows` で端末を指定します
（UDID は `xcrun simctl list devices booted` で確認できます）。

書き方の注意:

- iOS では、押せる番組行が中の文字（アートワークの頭文字、番組名、補足）を「台, 台所サイエンス, ことこと研究会」のように
  1つにつなげて読み上げます。Maestro の文字指定は全体一致の正規表現なので、`".*台所サイエンス.*"` のように部分一致で書きます。
  エピソード行も同じです。
- `accessibilityLabel` を付けたボタンは、表示の文字ではなく読み上げ名で探します（例: 速度のボタンは `"再生速度 1倍"`）。
  カードやフォローボタンも読み上げ名を付けているため、同じです（例: `"台所サイエンス、1位・科学"`、`"夜ふかし雑談所をフォロー"`）。
- iOS では、選択状態を `checked` 属性ではなく値として読み上げます。設定の選択肢は `"radio button, checked"`、
  フォローボタンは `"checked"`／`"unchecked"` を、`below` や `rightOf` で位置を絞って確かめます。
- ヘッダーの戻るボタンは、ID（`BackButton`）で押します。読み上げの名前は iOS の版で変わります
  （iOS 18 では前の画面名、iOS 27 では `Back`）。
- 入力欄に文字を入れ直すのは不安定です（「追加」を押すと入力欄から外れ、消すときのカーソル位置も定まらない）。
  別の URL を試すときは、画面を開き直します。
- 画面の下端にある行のボタンはタブバーと重なり、タブが押されることがあります。画面の中ほどにある要素を使うか、先にスクロールします。

CI では実行していません。macOS のランナーとシミュレータが必要なため、今後検討します。

## CI

GitHub Actions（`.github/workflows/ci.yml`）で、`main` への push と pull request のたびに、
Expo の版の確認、型チェック、lint、テストを実行します。Node.js 24 と、corepack で有効にした Yarn 4 を使います。

- Expo の版の確認（`yarn expo install --check`）は、SDK と版が合わない依存パッケージがあると失敗します。
  直すときは `yarn expo install --fix` を実行します。

### 依存パッケージの自動更新（Dependabot）

`.github/dependabot.yml` で、依存パッケージの更新を月1回、まとめて PR にします。

| 対象 | 届く更新 | PR |
| --- | --- | --- |
| `expo` | patch と、SDK の更新（例: 58 → 59） | 月1本にまとめる |
| `expo-*`、`@expo/*`、`react-native-*` | 同じ SDK の中の patch だけ | `expo` と同じ PR にまとめる |
| `react`、`react-dom`、`react-native` | 届かない（Expo が版ちょうどで指定するため） | なし |
| `typescript` | patch だけ（Expo SDK 58 は `~6.0.3` を求めるため） | その他と同じ PR にまとめる |
| `eslint` | minor と patch（`eslint-config-expo` 58 は ESLint 10 で動かないため） | その他と同じ PR にまとめる |
| その他のパッケージ | minor と patch | 月1本にまとめる |
| その他のパッケージのメジャー更新 | 1パッケージずつ | 出たときだけ。同時に開くのは最大3本 |
| GitHub Actions | すべて | 月1本にまとめる |

- 公開から7日たった版だけを提案します（`cooldown`）。
- `react`、`react-dom`、`react-native` は patch でも上げると `yarn expo install --check` が失敗するため、すべて対象外です。
- Expo の SDK を上げる PR（`expo` だけが上がる）は、CI の「Expo の版の確認」で失敗するのが普通です。
  その PR のブランチで `yarn expo install --fix` を実行し、ほかのパッケージを新しい SDK の版に揃えてからマージします。
  このとき `typescript` と `eslint` の ignore も見直します。
- 脆弱性の修正（security updates）は、リポジトリの設定でオンにした場合、この制限とは別に届きます。
- `resolutions` で固定した `minimatch` と `glob` は、Dependabot が更新を提案しても固定した版のままになります。

## 画面遷移

- 起動するとホームタブを開きます。
- 番組詳細は、開いたタブの画面履歴に積みます。戻ると、そのタブで開く前の画面に戻ります。
  - URL は `/<タブ名>/show/<番組ID>` です（例: `/discover/show/s2`）。
- 設定はホーム右上のプロフィールアイコンから開きます。
- 続きから再生のカード、トップ番組のカード、注目の特集は、それぞれ次のように動きます。
  - 続きから再生のカード: 右の再生ボタンで、その場で再生を始める（再生中の回では一時停止）。再生画面は開かない
  - トップ番組のカード、注目の特集: 表示中のタブの中で番組詳細を開く
- エピソード行を押すと再生を始め、タブバーの直上にミニプレイヤーを出します。再生画面は開きません。
- ミニプレイヤーは3つの領域に分かれます。
  - アートワークとエピソード名: 再生画面を開く（URL は `/player?tab=<タブ名>`）
  - 番組名: 表示中のタブの中で番組詳細を開く
  - 右端: その場で再生／一時停止。一時停止中もミニプレイヤーは残る
- 番組詳細の入口と戻り先は次のとおりです。どの入口でも、開いたタブの画面履歴に積み、ヘッダーの戻るボタンで元の画面に戻ります。
  - ホーム: トップ番組のカード
  - 新着・おすすめ: 注目の特集、トップ番組のカード
  - ライブラリ: 登録済みの番組行
  - 検索: 番組の結果（非表示の番組は、番組名と完全一致したときだけ末尾に出す）
  - ミニプレイヤー・再生画面: 番組名
- 検索画面の下の「＋ RSS の URL で追加」から、検索タブの中に追加画面を開きます（URL は `/search/add-feed`）。
  読み込めたら追加画面を番組詳細に置き換えるため、番組詳細から戻ると検索画面に戻ります。失敗したときは追加画面にとどまります。
- 番組詳細の「⋯」やエピソードのメニューは、画面の下から出るシートで開き、「閉じる」か背景を押すと番組詳細に戻ります。
- 再生画面は上部の「⌄」で閉じます。番組名を押すと、再生画面を閉じてから、開く前のタブの中で番組詳細を開きます。
  どちらも再生は止めません。

## 再生まわりの仮定

手書きメモと実装方針で決まっていない点を、次のように仮に決めています。

- RSS で追加した番組の回は、フィードに書かれた音声の URL から鳴らします。長さが書かれていない回は「長さ不明」と出し、
  音声を読み込んだら実際の長さ（秒未満は切り捨て）に直します。長さがわかるまでは、進む・戻るで位置を動かしません。
  音声の URL がない回は「⊘ 音声なし」と出し、押せないようにします。
- 音声は expo-audio で鳴らします（2026-11-03 導入）。架空の番組の音声は外部から取らず、アプリに同梱します。
  中身は、架空のエピソードごとに書いた短い原稿（番組名・タイトル・概要と本文）を macOS の読み上げ（`say`）で
  音声にしたもので、長さは 1〜2 分です。番組ごとに声を変えています。
  作り直すときは `sh scripts/make-audio.sh` を実行します。
- 架空データの再生時間（`mock.ts` の `duration`）は、同梱の音声の長さ（秒未満を切り捨て）に合わせています。
  原稿を変えて音声を作り直したら、`make-audio.sh` が表示する長さに合わせて `duration` も直します。
  途中まで聴いた回の位置も、短い音声に収まるよう 40 秒（第18回）と 50 秒（その31）にしています。
- 再生位置は reducer が持ち、音声の実際の位置（0.5 秒ごとの知らせ）で書き換えます。
  15秒戻る・30秒進む・スライダーは、reducer と音声の両方の位置を動かします。
  回を切り替えたときは、音声を読み込んでから記録の位置へ移って鳴らします。
- 音声が最後まで鳴ったとき、または再生位置が再生時間に届いたときに、再生済みにします。
- 音声を読み込めないとき（同梱の音声がない回、読み込みの失敗）は、一時停止にして、再生画面に
  「音声を読み込めませんでした。再生を押すと、もう一度試します。」と出します。ミニプレイヤーは残します。
- 消音モード（iPhone のサイレントスイッチ）でも鳴らし、ほかのアプリの音とは混ぜません。
- 電話などで OS が音声を止めたときに、アプリの再生状態を一時停止に合わせる処理は、まだありません。
- 1分に満たない長さは「残り20秒」のように秒で表します。
- 途中まで聴いた回は、記録した再生位置から始めます。再生済みの回と、まだ聴いていない回は最初から始めます。
- 再生位置は、再生を始めたとき、一時停止・移動したとき、再生中は音声の位置が知らされるたびに記録し、端末に保存します。
- 最後まで再生すると、再生状態を idle に戻し、ミニプレイヤーを閉じます。次の回の自動再生はまだありません。
- 再生速度は 0.8×、1.0×、1.25×、1.5×、2.0× を順に切り替えます。新しく再生を始める回は、番組ごとの速度があれば
  それを、なければ設定画面の速度を使います。設定画面で速度を変えても、再生中の回の速度は変えません。
- ミニプレイヤーを明示的に閉じる操作の形は未確定のため、`close()` だけを用意し、画面には操作を置いていません。
- エピソード名と番組名をそれぞれ 44pt 以上の高さで押せるよう、ミニプレイヤーは2段にしています。
- 再生画面の「⋯」は、再生速度、保存済みへの追加（保存済みなら外す）、番組の非表示／再表示が使えます。キューを表示は「準備中」として
  無効の状態で表示します。共有は公開URLを用意するまで、「問題を報告」は送信先が未設計のため置いていません。
- 再生画面下部のキューと出力先は、キュー画面と出力先の一覧がまだないため「準備中」として無効にしています。

## 保存の仮定

- 保存は端末の中だけです（expo-sqlite の `podcast.db`）。外へは送りません。
- 保存がないもの（初めて開いたとき）は、架空のデータを初期値にします。
- 残すのは、設定（再生速度、テーマ）、再生位置の記録、フォロー、保存済み、非表示、番組ごとの速度、RSS で追加した番組と
  そのエピソード（読み込んだ音声の長さを含む）です。
- 再生中の回とミニプレイヤーは残しません。開き直すと再生していない状態で始まり、続きから再生で途中から聴けます。
- 非表示にした番組も、追加した番組の写しは消しません。設定から再表示できます。
- 開けない・書けないときは、開発者向けの警告（`[storage]`）を出し、アプリの中だけで動き続けます。
  その場合は、終了すると架空データの状態に戻ります。利用者への知らせはまだ出しません。
- 表の形を変えるときは、`storage.ts` の `SCHEMA_VERSION` を上げ、`migrate` に移し方を足します。

## 取り直しの仮定

- アプリを開いたときと前面に戻ったときに、フォロー中で非表示でない、RSS で追加した番組を取り直します。
  最後に取ってから30分たっていない番組は取り直しません。最後に取った時刻は端末に保存します（追加したときも残します）。
- 番組詳細とライブラリの登録済みで下に引っ張ったとき、番組詳細の「⋯」の「フィードを更新」を押したときは、
  間隔によらず取り直します。
  「フィードを更新」は、引っ張る操作がしにくい場合のために置いています。
- 取り直すと、番組の情報とエピソードを新しいフィードに入れ替えます。番組とエピソードの ID は変えないので、
  再生位置・保存済み・番組ごとの速度は残ります。フィードから消えた回は、前のまま残します。
  フィードに長さがない回は、前に読み込んだ音声の長さを引き継ぎます。
- フィードが移転先（`itunes:new-feed-url`）を知らせていれば、次からは移転先を取ります。番組 ID は最初に追加した URL から
  作ったままにします。HTTP のリダイレクトは、恒久的か一時的かを fetch で区別できないため、URL を書き換えません。
- 取り直せなかったときは、前に読み込んだ内容をそのまま出します。自動の取り直しでは知らせず、番組詳細に
  「⚠ フィードを更新できませんでした。前に読み込んだ内容を表示しています。」と理由を出します。
  ライブラリで引っ張ったときは、更新できなかった番組の数を出します。失敗の状態は保存せず、取り直せたら消えます。
- 番組詳細の「この番組について」に、最後にフィードを取れた時刻を「フィードの更新: 11月4日 18:06」の形で出します
  （端末の時間帯）。取り直せなかったときは、失敗の知らせにも「前回の更新」として出します。
- 架空のデータの番組にはフィードがないため、取り直しません。

## 主要画面の仮定

手書きメモとワイヤーフレームで決まっていない点を、次のように仮に決めています。

- 「あなたのトップ番組」は、再生位置の記録の件数が多い番組から並べます。件数が同じなら、最近聴いた番組を先にします。
- 「未再生」は、一度も再生していないエピソードの本数です。途中まで聴いた回は含めません。
- 注目の特集は、番組を1つ取り上げる架空のデータ（`mock.ts` の `features`）です。選び方は未設計です。
- 履歴の再生位置は「0:50まで再生・残り36秒」の形で出します。
- 設定のテーマは、アプリだけの外観を切り替えます（`Appearance.setColorScheme`）。OS の設定は変えません。
- 設定の「プロフィール」「次の話を再生」「ストレージ」は、中身が未設計のため「準備中」にしています。
- 検索語を入力したままでも、1回のタップでフォローボタンなどが反応するよう、キーボードを出したまま押せるようにしています。
- ヘッダーには、どの画面でも背景色を付けます（`TabStack.tsx` の `useHeaderOptions`）。iOS 26 以降は付けないと
  ヘッダーが透け、設定などの画面の上の中身がヘッダーの裏に隠れるためです（iOS 27.2 のシミュレータで確認）。

## 補助画面の仮定

`../docs/show-detail.md` で決まっていない点と、まだ作っていない点を、次のように扱っています。

- 番組詳細のシートは1つだけ使い、中身を切り替えます。
  iOS でモーダルを閉じながら別のモーダルを開くと、表示されないことがあるためです。
- 「元に戻す」付きの通知は5秒（スクリーンリーダー使用中は10秒）で消えます。新しい通知を出すと、前の通知は消えます。
- 「保存済みと履歴も削除する」をオンにして非表示にしたときは、通知が消えてから（または画面を離れたときに）削除します。
  それまでは「元に戻す」で削除も取り消せます。再生中の回の履歴を削除した場合、再生を続けると記録し直します。
- 番組だけの再生速度は、新しく再生を始める回に使います。再生中の回の速度は変えません。
- 保存済みと履歴の行からの「番組を再表示」は、ライブラリの行にまだメニューがないため置いていません。
  再表示は番組詳細の「⋯」、再生画面の「⋯」、設定の「非表示にした番組」から行います。
- 非表示にしたときのキューからの除外と自動再生の停止は、キューと自動再生がまだないため対象外です。

## 開発時の約束

- 番組名、配信者名、アートワーク、再生履歴は架空のものを使います。実在するものは使いません。
- 選択状態や再生状態は、色だけでなく形・太字・枠線・文字でも区別します。
- 主要な操作のタップ領域は最低 44pt にします（`theme.ts` の `MIN_TAP`）。
- 新しいパッケージを入れる前に、必要かどうかを確認します。fast-xml-parser（RSS の読み取り）は 5.11.2 に固定しています。
  expo-sqlite（端末への保存）は `yarn expo install` で SDK 58 に合う版を入れています。
- Expo の API は SDK ごとに変わるため、コードを書く前に SDK 58 のドキュメントを確認します（`AGENTS.md` を参照）。

## 依存パッケージの版の固定

脆弱性（GHSA-g3hv-75wg-m249、GHSA-3g3m-2fjr-6pw4）を避けるため、`package.json` の `resolutions` で
間接的に使われる `minimatch` を 11.0.3、`glob` を 14.0.3 に固定しています。
ESLint や Expo が求める版（`minimatch` 3／10、`glob` 13）より新しいメジャー版を、強制的に使わせています。

- `minimatch` 11 は `require('minimatch')` を関数として呼べません。eslint-plugin-react と eslint-plugin-import の
  一部のルール（`react/jsx-pascal-case`、`import/no-unassigned-import`、`import/extensions` など）はその呼び方をしているため、
  有効にすると lint が `TypeError: ... is not a function` で止まります。いまの設定ではどれも使っていません。
- ESLint のルールを足したら、`yarn lint` が落ちないか確かめてください。
- ESLint・Expo・Jest が修正版に対応したら `resolutions` を外し、`yarn install` で元の版の決め方に戻します。
- `resolutions` を外したら、`glob` が 14.0.2 以上、`minimatch` が 11.0.1 以上になっているかを手で確かめます。
  Dependabot は `resolutions` を考慮せずに誤検出したため、アラート #1・#2 は閉じました。そのため、自動では知らせが来ません。
  確かめるには `yarn why glob` と `yarn why minimatch` を実行します。
